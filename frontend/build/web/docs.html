MIZAN (ميزان) — FINANCIAL SAFETY INSTRUMENT

Measure Before You Trust.

A highly detailed architectural breakdown of the MIZAN multi-vector heuristic risk engine and the Explainable AI (XAI) dashboard.

1. The Core Philosophy & Problem Statement

With the explosive adoption of UPI (Unified Payments Interface) in India, cybercriminals no longer rely on complex hacking or brute-force attacks. Instead, they rely entirely on Social Engineering. They manipulate victims into authorizing payments or clicking malicious links by creating a false sense of urgency, fear, or fake rewards.

The "Black Box" Problem: Most traditional anti-spam systems act as black boxes. They output a binary "Fake" or "Safe" result without context. If a user doesn't understand why a message is dangerous, they are likely to ignore the warning.

The Solution: MIZAN (ميزان - The Scale). MIZAN is an advanced, evidence-based forensic instrument. Instead of just flagging a message as "Fake", MIZAN acts as an Explainable AI (XAI) dashboard. It parses the payload, weighs the threat vectors on a 0-100 scale, and breaks down EXACTLY why a message is dangerous, educating the user on the specific tactics used by the scammer.

2. System Architecture

The project is built on a high-performance Client-Server architecture optimized for offline-ready, zero-latency processing (Phase 1).

Frontend Thin-Client (Flutter)

A cross-platform (Windows/Web/Mobile) UI designed with a premium, sophisticated aesthetic. It features a Verification Desk that accepts text payloads, URLs, and QR code image uploads. The UI dynamically adapts its color palette (Safe/Suspicious/High Risk) based on the backend's findings.

Heuristic Backend (FastAPI / Python)

A lightweight REST API housing the "Mizan Measurement Engine". It executes deterministic rules and live network forensics (DNS, HTTP tracing) to analyze payloads synchronously. It generates structured JSON reports containing `why_flagged` and `recommended_action` arrays.

3. The Multi-Vector Heuristic Engine (Deep Dive)

The backend does not rely on simple word counting. It utilizes a 4-Vector contextual evaluation matrix to catch sophisticated attacks.

Vector A: Social Engineering & Coercion (Utility Scams)

Scammers use emotional manipulation to bypass logical thinking. The engine cross-references "Urgency" triggers ("immediately", "within 24 hours") with "Fear" vectors ("fine", "arrest").

Specifically targeted for India: The engine has dedicated logic for the Electricity Disconnection Scam. If it detects utility keywords ("electricity", "unpaid bills", "disconnected") alongside urgency, it immediately flags a Critical Extortion Threat.

Vector B: Payment Behavior Conflict (The Golden UPI Rule)

The most devastating UPI scam is tricking a user into entering their UPI PIN to receive money (e.g., OLX scams, Fake Cashbacks).

The Logic: The engine looks for a contradiction in payment flow. If it detects intent to receive ("receive", "claim", "credited") in the same payload as an authentication action ("enter pin", "scan qr"), it triggers the highest possible risk score. You never need a PIN to receive money.

Vector C: Conversational Spear Phishing (Hinglish Support)

Traditional engines fail when a scammer poses as a friend using conversational language (e.g., "Bhai mera phone kharab hai, urgent paise bhej"). MIZAN contains a dedicated Hinglish Impersonation Module.

The Logic: It calculates an intersection of three vectors: Familiarity ("bhai", "dost") + Emergency ("kharab", "stuck") + Action ("paise bhej", "gpay kar"). When these align, the system realizes this is a hijacked account or "new number" scam and advises the user to call the person on their old known number.

Vector D: Advanced URL & Network Forensics

This module goes beyond text parsing and actively pings the internet to verify domain integrity.

DNS Resolution Checking

The engine uses Python's dns.resolver to query A-Records. Cybercriminal domains are often blackholed or taken offline quickly. If the domain fails to resolve to an IP, MIZAN flags it as a disposable/dead domain.

Shannon Entropy (DGA Detection)

Malware uses Domain Generation Algorithms (DGA) to create random URLs (e.g., http://kjhsdgfks.com). MIZAN calculates the Shannon Entropy of the domain string. An entropy score > 4.0 mathematically proves the domain was machine-generated, not human-readable.

Redirect Tracing

Scammers hide malicious URLs behind short-links (bit.ly, tinyurl). MIZAN executes a live requests.head(allow_redirects=True) trace to unmask the true destination URL before analyzing it.

IP Obfuscation & Typosquatting

Flags URLs that bypass DNS and use raw IP addresses (e.g., http://192.168.1.1). It also catches Typosquatting by checking if the domain contains brand names (e.g., "hdfc") but doesn't end in the official .com or .co.in.

4. The Measurement Scale & Explainable AI (XAI)

Instead of a binary output, MIZAN places every payload on a 0 to 100 Risk Balance Index.

0 - 34: SAFE

Insufficient Evidence: MIZAN explicitly tells the user that while no heuristic threats were found, it doesn't prove the sender is legitimate. (Zero false promises).

35 - 69: SUSPICIOUS

Proceed with Caution: Ambiguous indicators detected (e.g., urgency without financial demands).

70 - 100: HIGH RISK

Fraud Vector Detected: Confirmed scam signatures. The engine outputs explicit reasons under "Why We Flagged This" and actionable advice under "What You Should Do".

5. Hackathon Defense & Phase 2 (Future Scope)

MIZAN is currently an MVP relying on a Deterministic Heuristic Engine. While incredibly fast (zero-latency) and effective, rigid rule-based engines can be bypassed by complex synonyms.

The Phase 2 Architecture: The current system is designed so that the heuristic dictionary can be cleanly swapped out for a fine-tuned Multilingual LLM (like BERT or Llama) for semantic intent detection. Phase 2 will also integrate Graph Neural Networks to analyze UPI ID transaction history and Metadata Reputation via APIs (e.g., Truecaller) to evaluate sender trust before ever analyzing the text.
